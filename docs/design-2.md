# 第二阶段系统与数据库设计

本系统在原有问卷创建、发布、填写和统计功能上，增加常用题目独立保存、固定版本复用、题库分享、使用情况查询和跨问卷统计。本文介绍系统结构、MongoDB 文档模型及关键处理逻辑。第一阶段设计见 [design.md](design.md).

## 1. 系统说明

系统继续采用前后端分离结构：Vue 3 + Vite 提供页面，FastAPI 接收 HTTP 请求并处理业务，PyMongo 负责访问 MongoDB。浏览器不直接连接数据库，业务数据统一保存在 MongoDB 中。

后端保留单个服务，按职责划分为五个模块：

| 模块 | 主要职责 |
| --- | --- |
| 用户账号 | 注册、登录、密码验证和当前用户识别 |
| 问卷管理 | 草稿编辑、题目与跳转配置、固定版本选入与替换、发布、截止和关闭 |
| 填写与提交 | 计算有效答题路径、校验答案、检查重复限制和保存答卷 |
| 题目与题库 | 独立题目、版本历史与恢复、题库组织、分享权限和使用查询 |
| 结果统计 | 本卷统计、固定版本跨问卷汇总、数字分布和文本分页 |

前端在原工作台中提供“我的题目”和“我的题库”，问卷编辑器支持临时题与可复用题混合使用。选题入口包括我的题目、我的题库和输入他人题库 ID；问卷统计与题目详情共用全局分析入口。前端负责操作提示，后端独立执行权限、配置和答案校验。

系统区分两类题目：临时题只属于当前问卷；可复用题有独立身份和固定版本，可以被多份问卷选用。两类题目均支持填写与本卷统计，只有可复用题支持独立版本管理、分享、跨问卷使用查询和全局统计。同名或内容相同的题目不自动视为同一道题。

## 2. MongoDB 数据库设计

### 2.1 集合划分与设计理由

系统保留原有三个集合，增加独立题目和题库集合，默认数据库为 `survey_pro1`。

| 集合 | 一份文档表示 | 与其他数据的关系 |
| --- | --- | --- |
| `users` | 一个用户账号 | 由问卷、答卷、题目和题库引用用户 ID |
| `surveys` | 一份问卷及完整配置 | 题目、选项、校验和跳转内嵌；可复用题增加固定版本来源 |
| `responses` | 一次成功提交的答卷 | 引用问卷和填写账号，答案仍关联问卷内部题目、选项 ID |
| `questions` | 一道可复用题目及其版本历史 | 保存创建者、当前版本指针和内嵌版本内容 |
| `question_banks` | 一个题库及成员关系 | 引用创建者和逻辑题目 ID，不复制版本内容 |

问卷填写需要整体读取配置，因此继续保留内嵌题目。独立题目负责统一身份和版本，问卷保存实际选用内容的快照，使源题修改后仍能按原内容解释答案。这里允许有限的内容冗余，以保证已有问卷稳定。

版本通常随题目一起查看，嵌入同一文档便于读取和条件原子更新；题库只承担分类与分享职责，因此仅保存题目引用。同一道题加入多个题库不会产生多份内容。答卷继续独立保存，使用关系和统计结果按实际数据查询，不另建需要同步维护的集合。

### 2.2 questions：可复用题目

| 字段 | BSON 类型 | 含义 |
| --- | --- | --- |
| `_id` | ObjectId | 逻辑题目唯一标识，关联该题所有版本 |
| `owner_id` | ObjectId | 创建者，引用 `users._id` |
| `current_version_id` | String | 当前默认选用的版本 ID |
| `max_version` | Integer | 历史最高版本号，用于生成下一编号 |
| `revision` | Integer | 修订号，用于识别过期修改和并发冲突 |
| `versions` | Array of Documents | 固定版本历史 |
| `retired` | Boolean，可省略 | 转回临时题后标记停用；缺省视为可用 |
| `created_at`、`updated_at` | Date | 创建与最近修改时间 |

每个版本包含以下字段：

| 字段 | 结构或取值 | 含义 |
| --- | --- | --- |
| `id` | String | 固定版本唯一标识 |
| `number` | Integer | 递增版本号 |
| `parent_version_id` | String / Null | 本版基于哪个版本修改，v1 为 `null` |
| `content` | Document | 题型、题干、选项和校验参数 |
| `created_at` | Date | 版本保存时间 |

`content` 包含 `type`、`title`、`options` 和 `validation`，支持单选、多选、文本和数字四类题型，选项使用 `{id, label}`。是否必答、顺序和跳转属于具体问卷，不保存到独立版本中。固定版本内容不覆盖，后续修改保存为新版本。

### 2.3 surveys：问卷来源与选项映射

问卷保留原标题、状态、匿名与重复开关、截止及内嵌题目配置。可复用题在原结构上增加来源和映射，临时题不要求这些字段。

| 字段 | 所在位置 | 含义 |
| --- | --- | --- |
| `id` | 问卷题目 | 问卷内部稳定 ID，用于答案和跳转关联 |
| `source.question_id` | 问卷题目 | 独立逻辑题目 ID 的字符串形式 |
| `source.version_id` | 问卷题目 | 实际选用的固定版本 ID |
| `source.version_number` | 问卷题目 | 实际版本号，用于展示 |
| `source_option_id` | 问卷题目的选项 | 对应固定版本的选项 ID |

下面展示一个引用单选题的简化结构，ID 均为示意值：

```json
{
  "id": "q_internal",
  "type": "single",
  "title": "是否学过 MongoDB？",
  "required": true,
  "options": [
    {"id": "opt_yes", "label": "是", "source_option_id": "vo_yes"},
    {"id": "opt_no", "label": "否", "source_option_id": "vo_no"}
  ],
  "validation": {},
  "jump_rules": [],
  "source": {
    "question_id": "<logical_question_id>",
    "version_id": "<version_id>",
    "version_number": 1
  }
}
```

逻辑题目 ID 表示同一道可复用题，版本 ID 表示某次固定内容，问卷内部题目 ID 表示它在当前问卷中的具体位置。三者分开后，同一版本可在不同问卷或同卷多个位置出现，同时保留原答案与跳转的关联方式。

### 2.4 question_banks：题库

| 字段 | BSON 类型 | 含义 |
| --- | --- | --- |
| `_id` | ObjectId | 题库标识，字符串形式用于分享查找 |
| `owner_id` | ObjectId | 题库创建者 |
| `name` | String | 题库名称，去首尾空白后为 1～100 字符 |
| `question_ids` | Array of ObjectId | 本人创建的可复用题目 ID，不重复保存成员 |
| `revision` | Integer | 修订号，用于条件更新与删除 |
| `created_at`、`updated_at` | Date | 创建与最近修改时间 |

题库关联逻辑题目，展示其当前版本；实际选入问卷时再确定固定版本。移出成员或删除题库只改变组织关系，不删除题目、版本、问卷或答卷。系统不设置题目公开、私有状态，也不设置题库共享开关。

### 2.5 索引与校验边界

原用户名唯一索引、问卷列表索引、答卷部分唯一索引及最新答卷查询索引继续保留，新增以下索引：

| 集合 | 索引字段与顺序 | 用途 |
| --- | --- | --- |
| `questions` | `owner_id: 1, created_at: -1` | 查询本人的可复用题目 |
| `question_banks` | `owner_id: 1, created_at: -1` | 查询本人的题库 |
| `question_banks` | `question_ids: 1` | 查询题目是否仍属于创建者的题库 |
| `surveys` | `questions.source.question_id: 1` | 定位使用某道题的问卷 |

字段类型和业务规则由后端模型及逻辑校验，唯一性由数据库索引约束，跨集合引用由后端检查。题目和题库文档保存前检查 BSON 编码大小，超过项目设置的 15 MiB 上限时拒绝本次保存，保留原数据。

## 3. 关键逻辑说明

### 3.1 固定版本、恢复与并发修改

首次保存独立题目生成 v1，确认修改后保存下一固定版本，取消编辑不改变已有内容。恢复旧版本只切换 `current_version_id`，不复制或删除版本。已有 v1、v2、v3 时恢复 v1，再修改会生成 v4，并将来源版本设为 v1。

版本号表示内容版本，`revision` 表示管理数据是否发生变化，恢复版本也会增加修订号。修改时提交读回的修订号，数据库同时匹配所有者与原修订号执行更新；两请求使用相同修订号时仅一个成功，另一个返回 `409`。题库修改和删除采用相同的修订号检查方式。

### 3.2 问卷快照、跳转与校验

选入固定版本时，后端检查问卷所有权、草稿状态和题目选用权限，将版本内容保存到问卷末尾，并生成问卷内部题目、选项 ID 和来源映射。必答默认关闭，由问卷创建者独立设置。

普通草稿保存只能调整引用题目的必答、顺序和跳转，或删除该位置，不能伪造来源、修改固定内容或直接解除来源。替换版本使用专用操作，只能选择同一道逻辑题目的其他可用版本，保留原内部题目 ID、必答和跳转；新版使选项条件等引用失效时，拒绝整个更新。

发布后仍锁定问卷内容，源题新增版本、恢复版本或题库成员变化均不刷新已有快照。填写继续读取问卷配置，按第一阶段规则重算有效路径，检查必答、选项、长度、数值范围及手机号格式；路径外旧答案被拒绝，被跳过的必答题无需回答。

### 3.3 分享权限与使用情况查询

本人可管理和复用自己的题目。题目加入创建者任一题库后，其他登录用户可凭题库 ID 浏览并选用固定版本，但不能修改题目、恢复版本、管理他人题库或将他人题加入自己的题库。题目列表和题库列表仅显示本人数据，不提供公开搜索。

题目撤出创建者所有题库后，其他用户不能建立新引用；已有问卷继续使用原快照。已有引用者仅保留自己所用版本的读取、使用查询和对应全局分析权限，不能读取未引用的新版本。题目仍在创建者另一题库中时，继续允许分享选用。

使用查询直接从问卷题目的 `source` 定位引用，同一题目与版本须匹配同一数组元素。返回问卷名称、创建者、状态及所用版本等必要信息；自己的草稿可见，他人草稿隐藏。能够查询题目使用情况，不代表能够读取他人完整问卷、答卷或本卷统计。

### 3.4 临时题转换与旧数据兼容

自己的草稿、已发布或已关闭问卷中的临时题均可保存为可复用题。后端创建独立 v1，为当前原题补充来源和选项映射，保留内部 ID、内容、必答、跳转及答卷，使原答案可进入该版本的全局统计。条件更新冲突时清理本次新建题目，避免留下无关联副本。

转回临时题时，按所有版本检查引用问卷数：未引用可直接移出；仅一份本人问卷引用时，解除该卷各位置的来源与映射；多份引用或唯一引用属于他人时拒绝操作。独立题目标记 `retired` 并保留版本内容，不再向列表、选题和分析入口提供；题库中原组织关系可手动移出。

旧问卷没有来源时继续按临时题处理，不按同名或相同内容自动合并，不要求清空数据库或批量迁移。旧题目没有 `retired` 时视为可用，旧 `is_public` 字段不参与权限判断；题库中的历史他人题成员不展示，也不传播分享权限。

### 3.5 本卷与跨问卷统计

本卷统计保留原口径：统计全部成功提交份数和按账号去重的参与人数，题目结果取每账号最新的一整份答卷。跨问卷统计以固定版本为单位，先找到引用该版的已发布或已关闭问卷，再逐卷按账号取最新整份答卷，按内部题目 ID 提取各位置答案。

| 统计内容 | 计算方式 |
| --- | --- |
| 引用问卷数 | 引用该版的已发布或已关闭问卷数，包含已截止问卷，不含草稿；同卷只计一次 |
| 有回答问卷数 | 上述问卷中至少有一次有效回答的问卷数 |
| 有效回答数 | 各卷最新答卷中该版本各出现位置的非空回答次数 |
| 单选、多选 | 通过选项来源映射回固定版本，计算次数及占有效回答数的比例；多选比例总和可超过 100% |
| 数字 | 计算平均值，按相同数值分组并升序分页展示频次与占比 |
| 文本 | 计算有效回答数，分页返回非空文本，相同内容分别保留 |

同一账号跨问卷的回答分别计数，同版同卷多个位置也分别计数，因此有效回答数不是跨卷去重人数。不同版本及同名独立题不混合，临时题只参与本卷统计。空答和跳过不计，数字 `0` 计入；最新整份答卷缺少某题时，不从历史补回旧答案。

数字均值和占比按全部有效回答计算，不随分页改变。文本按问卷 ID、账号 ID 和答卷中位置固定遍历，只返回当前页内容。全局响应不附带填写者身份、来源问卷、答卷 ID 或其他题答案，文本自身写入的身份信息不作自动脱敏。

统计实时计算，不保存额外结果副本。跨问卷查询逐卷执行聚合；临时题转换等跨集合操作采用条件更新和失败清理，不具备完整跨集合事务保证，进程中断恢复和大样本性能仍有验证边界。
不解析HTML，各入口同时适用。无新集合/缓存/迁移。查询逐卷执行，尚无性能验收或跨集合快照事务保证。
