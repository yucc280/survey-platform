# 第二阶段测试说明

## 1. 测试程序设计

测试代码位于 [`backend/tests/`](../backend/tests/)，沿用第一阶段的 Python `unittest` 和 FastAPI `TestClient`。每个测试按“准备隔离数据 → 发起接口请求或调用函数 → 断言状态码、响应及数据变化 → 清理环境”的流程执行。

| 测试文件 | 主要检查内容 |
| --- | --- |
| `test_auth.py` | 原注册、登录、密码哈希和令牌认证回归 |
| `test_surveys.py` | 原问卷管理、题型配置、跳转、生命周期、权限及草稿删除回归 |
| `test_responses.py` | 原答题路径、答案校验、匿名、重复限制和提交保存回归 |
| `test_statistics.py` | 原本卷最新整份答卷统计、选项计数、平均值和匿名信息保护回归 |
| `test_questions.py` | 独立题目、版本历史与恢复、固定版本引用、快照保护及临时题转换 |
| `test_sharing_banks.py` | 题库管理、ID分享、题目权限、使用查询及并发修改 |
| `test_global_statistics.py` | 固定版本跨问卷统计、选项映射、数值分布、文本分页及信息保护 |

测试结合两类环境：内存替身用于检查业务分支，真实 MongoDB 用于验证读写、聚合和索引约束。真实库测试使用随机命名的独立临时数据库，并设置清理逻辑，不使用业务数据库。第二阶段在第一阶段测试基础上追加用例，同时保留原功能回归。

前端沿用现有 Node 纯逻辑测试，并执行 Vite 生产构建。已有桌面浏览器联调记录用于补充页面流程检查。

## 2. 核心测试用例

下表归纳已有自动测试中的代表性场景，不逐条展开全部测试方法。输入与预期依据现有测试及原测试记录，实际输出概括已有通过的断言，不表示检查了响应中的全部字段。第一阶段核心用例见 [testing.md](testing.md)。

公共数据：A、B 为不同测试账号；独立题目覆盖单选、多选、文本和数字四种题型；v1、v2 等表示同一道题的不同版本。题目、版本、问卷和选项 ID 使用接口返回值。共享按最终题库 ID 规则检查，不再采用开发早期的公开、私有状态。

| --- | --- | --- | --- | --- |
| T01 原功能回归 | 执行账号、问卷、填写及本卷统计测试 | 原注册登录、创建与添加题目、跳转、校验、提交和统计场景 | 原接口状态码、保存内容及统计口径符合既有断言 | 符合预期，通过 |
| T02 创建独立题目 | 创建四题型，再提交非法配置 | 合法题型配置；含 `required`、`jump_rules` 的独立题配置；非法范围 | 合法创建 `201`；非法配置 `422`，不写入版本 | 符合预期，通过 |
| T03 版本与恢复 | 保存 v1～v3，恢复 v1，再编辑保存 | 历史版本 ID、当前 `revision` | 恢复 `200`，历史仍为三版；再次保存 `201`，生成 v4、来源为 v1，旧内容不变 | 符合预期，通过 |
| T04 并发保存版本 | 同步两个请求保存同一道题 | 相同 `revision`、不同修改内容 | 状态码为 `201` 和 `409`，历史只增加一版 | 符合预期，通过；真实 MongoDB |
| T05 混合引用与必答 | 同卷保存复用题和临时题，在另一卷设置不同必答要求 | 固定版本来源、原内部 ID、各卷 `required` | 保存 `200`；来源和内部 ID 保留，必答按具体问卷设置 | 符合预期，通过 |

| T07 已发布问卷保护 | 发布 v1 问卷，修改或恢复源题版本，再填写和统计 | 原 v1 快照、数字答案 0；修改已发布问卷请求 | 填写内容不变，提交 `201`、本卷平均值 0；修改、选入或替换版本 `409` | 符合预期，通过 |
| T08 题库管理与冲突 | 创建、改名、加入、移出成员，检查过期与并发修改 | 本人题目、重复成员、相同或过期 `revision` | 正常操作 `201`/`200`，成员不重复、不复制题目；过期修改 `409`；并发修改仅一次成功 | 符合预期，通过；含真实 MongoDB 并发测试 |
| T09 ID分享与权限 | B 按 ID 读取 A 的题库，再尝试管理；检查未入库题访问 | 题库 ID、未登录请求、跨用户管理及加入他人题目 | 登录可只读查找；未登录 `401`；越权管理、加入他人题及未入库题越权访问 `404`；列表仅含本人题库 | 符合预期，通过 |
| T10 撤销共享与旧引用 | 删除题库后查原 ID，读取已用版本并尝试新增引用 | 已有问卷来源、未引用新版、过期删除 `revision` | 原题库 ID `404`，过期删除 `409`；旧问卷仍可发布填写，已用版本及分析可读；无权新增引用 `404` | 符合预期，通过 |
| T11 使用关系查询 | 按题目或版本查询，再删除引用草稿 | 不同创建者的草稿、发布及关闭问卷；分页参数 | 隐藏他人草稿及其数量；仅返回允许的使用信息；删除草稿后引用消失，原题保留 | 符合预期，通过 |
| T12 临时题转换 | 在草稿、发布及关闭问卷转换四题型，再按允许条件转回 | 原题内容、内部题目及选项 ID、必答、跳转和已有答卷 | 转换建立 v1 来源及选项映射；转回解除来源；原内容、ID、答卷与本卷统计保留 | 符合预期，通过 |
| T13 转回限制与冲突 | 尝试多卷或他人引用下转回，模拟转换更新冲突 | 两个引用卷、唯一他人引用、过期 `revision`、条件更新冲突 | 不允许转回时 `409`；非本人操作 `404`；更新冲突 `409`，清理新副本，原数据保留 | 符合预期，通过 |
| T14 跨卷统计口径 | 同账号在 A 卷填 20 后填 30，在 B 卷填 40；纳入关闭及截止历史 | 另有无有效回答的引用卷和草稿 | 引用问卷 3、有样本问卷 2、有效回答 2、均值 35；每卷取最新整份，跨卷不去重，草稿排除 | 符合预期，通过 |
| T15 选项映射与版本 | 不同卷引用同版题目，再加入新版及同名独立题 | 不同内部选项 ID；单选各选一次；多选 A/B 与 B/C | 同版按映射汇总；单选各 1 次、50%；多选次数 1/2/1、占比 50/100/50%；不同版本和独立题隔离 | 符合预期，通过 |
| T16 空答、跳过与多位置 | 重填时跳过或留空旧题，同卷两处引用同一版本 | 旧值 9、后续 0 及空答；两处分别填 20、40 | 0 参与统计，最新空答或跳过不回填；无样本均值 `null`；两处分别计数、均值 30 | 符合预期，通过 |
| T17 数值分布与边界 | 查询分页，再检查大数平均值 | 10/0/20/10，`offset=1`、`limit=1`；两个 `1.7e308` | 回答 4、均值 10，当前页数值 10 计 2 次、50%；越界页为空，非法分页 `422`；大数均值有限 | 符合预期，通过 |
| T18 文本明细与隐私 | 有权读取者查询实名及匿名文本，检查分页和重复内容 | 换行、HTML 字面文本、相同内容、最新替换、空答及跳过 | 保留文本及重复项，不附带身份、问卷来源或整份答案；总数与有效回答数口径一致；最新空答或跳过不回填 | 符合预期，通过 |
| T19 文本版本与权限 | 查询同卷多个位置、不同版本及撤销题库后的文本 | 已引用版本、未引用新版、分页及非法参数 | 多位置分别计数、版本隔离；撤销后已用版本仍可读，无权访问新版被拒绝；分页及参数校验符合断言 | 符合预期，通过 |

## 3. 测试结果与分析

最近一次完整后端回归记录为 **2026-10-29，共运行 168 项，全部通过，失败 0 项、异常 0 项、跳过 0 项**，耗时 **45.527 秒**。其中 86 项为非真实库测试，82 项为真实 MongoDB 测试；同一业务用例在不同环境执行会分别计数，因此不代表 168 种独立场景。本次文档改写没有重新运行测试，以上引用已有实际结果。

结果表明，现有断言覆盖的独立题目、版本恢复、固定快照、题库 ID 分享、临时题转换及跨问卷统计行为符合预期，原账号、问卷管理、跳转、校验、提交和本卷统计回归也通过。真实库测试还验证了版本保存、题库修改及原禁止重复提交的并发约束，以及实际聚合统计结果。

同次文本明细变更记录中，前端 **8 项纯逻辑测试全部通过，生产构建通过，共 20 个模块**。此前桌面浏览器联调已验证版本查看与恢复、草稿选题、固定版本填写、匿名提交、本卷及全局统计等核心流程；题库 ID 分享替代旧共享规则后，以及新增文本明细后，未重新完成对应的浏览器交互验收，不能将早期联调结果作为这两项新流程的页面通过结论。

本次范围以自动测试及已有桌面联调为主，不包含移动端、全浏览器、大规模并发或大样本性能测试；存储大小守卫使用调低上限模拟，未进行 15 MiB 大文档压力验证。
