# 系统与数据库设计

本系统支持用户注册登录、问卷创建与发布、条件跳转、答案校验、填写提交和结果统计。本文介绍系统结构、MongoDB 文档模型及后端关键逻辑；运行方法见项目根目录的 README，接口参数与调用示例见 `api.md`。

## 1. 系统结构

系统采用前后端分离结构：Vue 3 + Vite 提供页面，FastAPI 接收 HTTP 请求，PyMongo 负责访问 MongoDB。浏览器不直接连接数据库，业务数据统一保存在 MongoDB 中。

后端为单个服务，按职责划分为四个模块：

| 模块 | 主要职责 | 代码位置 |
| --- | --- | --- |
| 用户账号 | 注册、登录、密码验证、识别当前用户 | `backend/app/auth/` |
| 问卷管理 | 草稿编辑、题型与规则配置、发布、截止、关闭和草稿删除 | `backend/app/surveys/` |
| 填写与提交 | 重算答题路径、校验答案、检查重复限制、保存答卷 | `backend/app/responses/` |
| 结果统计 | 创建者权限检查、最新答卷筛选、计数与平均值计算 | `backend/app/stats/` |

`main.py` 负责应用入口与路由挂载，`database.py` 负责数据库连接、生命周期和索引。前端提供即时提示，后端独立执行最终权限与业务校验，数据库负责持久保存和唯一性约束。

## 2. MongoDB 数据库设计

### 2.1 集合划分与设计理由

系统使用 `users`、`surveys`、`responses` 三个核心集合，默认数据库为 `survey_pro1`。

| 集合 | 一份文档表示 | 与其他数据的关系 |
| --- | --- | --- |
| `users` | 一个用户账号 | 不保存问卷或答卷列表，由其他集合引用用户 ID |
| `surveys` | 一份问卷及其完整配置 | `owner_id` 引用用户；题目、选项、校验和跳转规则内嵌 |
| `responses` | 一次成功提交的答卷 | `survey_id` 引用问卷，`user_id` 引用填写账号 |

题目和规则属于问卷内部配置，通常整体读取、编辑和校验，因此嵌入同一问卷文档，便于一次读取与单文档原子更新。不同题型的校验参数不同，嵌套文档能够直接表达这些差异，无需机械地按关系表方式拆分题目、选项和规则。

答卷数量随提交持续增长，且需要独立查询和聚合，因此单独保存，避免把全部答卷追加到问卷文档中。用户同样独立保存，避免在各问卷中重复维护账号资料。

答案只保存题目和选项的稳定 ID，不复制题干、选项文字；统计实时计算，不维护额外统计副本。这样的引用和有限冗余减少了重复更新。发布后锁定问卷结构，使历史答案能够持续按同一配置解释。这些选择基于当前读取与更新方式，并不表示关系数据库无法实现相同业务。

### 2.2 users：用户

| 字段 | BSON 类型 | 含义 |
| --- | --- | --- |
| `_id` | ObjectId | 用户唯一标识 |
| `username` | String | 用户名，唯一且区分大小写 |
| `password_hash` | String | Argon2id 密码哈希，不保存明文密码 |
| `created_at` | Date | 后端生成的注册时间 |

用户名去首尾空白后为 3～30 字符，仅允许英文字母、数字和下划线。原始密码为 6～30 字符，不自动去空白或改变大小写。密码哈希由 `argon2-cffi` 生成，编码结果包含盐和参数，无需另建盐字段，也不向接口返回密码哈希。

### 2.3 surveys：问卷

| 字段 | BSON 类型 | 含义 |
| --- | --- | --- |
| `_id` | ObjectId | 问卷标识，字符串形式用于填写链接 |
| `owner_id` | ObjectId | 创建者，引用 `users._id` |
| `title`、`description` | String | 标题与说明 |
| `status` | String | `draft`、`published` 或 `closed` |
| `allow_anonymous`、`allow_repeat` | Boolean | 是否允许匿名、重复填写，默认均为 `false` |
| `deadline` | Date / Null | 截止时间；`null` 表示不设截止 |
| `questions` | Array of Documents | 按展示顺序保存的题目配置 |
| `created_at`、`updated_at` | Date | 创建与最近修改时间 |

每个题目包含以下字段：

| 字段 | 结构或取值 | 含义 |
| --- | --- | --- |
| `id` | String | 后端生成、问卷内唯一的稳定 ID |
| `type` | `single` / `multiple` / `text` / `number` | 单选、多选、文本、数字 |
| `title` | String | 题干 |
| `required` | Boolean | 是否必答，默认 `false` |
| `options` | `[{id, label}]` | 选项；填空题为空数组 |
| `validation` | Document | 当前题型适用的校验参数 |
| `jump_rules` | Array of Documents | 按优先级排列的跳转规则，无规则时为空数组 |

题目数组顺序决定展示顺序，不另外保存题号。修改文字或重排时保留题目、选项 ID，避免位置变化导致答案与跳转引用错位。新题、新选项先保存并取得 ID，再配置引用。

下面展示问卷中一个单选题的内嵌结构，ID 均为示意值，目标题须存在于同一问卷后方：

```json
{
  "id": "q1",
  "type": "single",
  "title": "是否使用过 MongoDB？",
  "required": true,
  "options": [
    {"id": "opt_yes", "label": "是"},
    {"id": "opt_no", "label": "否"}
  ],
  "validation": {},
  "jump_rules": [
    {
      "condition": {"operator": "equals", "value": "opt_yes"},
      "target": {"kind": "question", "question_id": "q3"}
    }
  ]
}
```

问卷标题为 1～100 字符、说明最多 1000 字符、题干为 1～200 字符；每份问卷最多 100 题，选择题有 2～30 个选项，选项文字为 1～100 字符。这些是当前实现范围，具体接口输入要求见 `api.md`。

### 2.4 responses：答卷

| 字段 | BSON 类型 | 含义 |
| --- | --- | --- |
| `_id` | ObjectId | 本次答卷标识 |
| `survey_id` | ObjectId | 引用 `surveys._id` |
| `user_id` | ObjectId | 填写账号，由登录身份取得，匿名时也保留 |
| `is_anonymous` | Boolean | 本次提交是否对创建者匿名 |
| `answers` | Array of Documents | 有效路径上的答案，每项为 `{question_id, value}` |
| `submitted_at` | Date | 后端生成的提交时间 |
| `single_submission` | Boolean | 禁止重复时为 `true`，由后端生成，用于部分唯一索引 |

`value` 按题型保存为选项 ID 字符串、无重复的选项 ID 数组、文本、整数或其他数值。有效路径中未回答的非必答题保存 `null`，被跳过的题不保存。答案片段示例如下：

```json
[
  {"question_id": "q1", "value": "opt_yes"},
  {"question_id": "q3", "value": 20},
  {"question_id": "q4", "value": null}
]
```

每次成功提交独立插入一份文档，不覆盖历史答卷，也不保存未提交的填写草稿。问卷和账号引用由后端检查；MongoDB 不会自动按这些字段执行外键校验。

所有日期以 BSON Date 按 UTC 保存，界面按北京时间输入与展示；接口中的 ID 为字符串，时间为带时区的 ISO 格式。

### 2.5 索引、初始化与校验边界

除各集合默认的 `_id` 唯一索引外，后端启动时自动创建以下索引：

| 集合 | 索引字段与顺序 | 用途 |
| --- | --- | --- |
| `users` | `username: 1`，唯一 | 按用户名查找，并防止并发注册同名账号 |
| `surveys` | `owner_id: 1, created_at: -1` | 支持创建者问卷列表查询 |
| `responses` | `survey_id: 1, user_id: 1`，部分唯一 | 仅约束 `single_submission=true` 的文档，限制同账号重复提交 |
| `responses` | `survey_id: 1, user_id: 1, submitted_at: -1, _id: -1` | 支持按问卷、账号及提交顺序读取答卷 |

部分唯一索引让禁止重复的答卷受到数据库约束，同时允许其他问卷保存同账号的多次提交。该方案依赖发布后重复策略保持不变。

启动流程检查 `JWT_SECRET` 至少为 32 字节，连接并 `ping` MongoDB，再建立索引；失败时不启动服务。创建索引会创建尚不存在的集合，空数据库无需手工建集合、导入账号或执行额外初始化脚本。

当前未配置 MongoDB 集合级 `$jsonSchema` 校验。字段类型与业务规则由 Pydantic 模型及后端逻辑校验，唯一性由数据库索引约束；绕过后端直接写库时，不会获得应用层的结构与业务校验保护。

## 3. 权限与问卷生命周期

登录使用有效期两小时的 HS256 JWT，后端检查签名、过期时间和用户存在性。创建者身份与填写者身份均从令牌取得，不接受客户端自行指定。管理和统计接口按问卷所有权检查，非法 ID、不存在和非本人问卷统一返回 `404`。

| 状态 | 允许操作与限制 |
| --- | --- |
| `draft` | 编辑配置、删除草稿；至少有一道合法题目后可发布 |
| `published` 且未到截止 | 可以填写；创建者可调整或取消截止时间、主动关闭 |
| `published` 且已到截止 | 拒绝填写与提交，不能延长或取消截止来恢复开放；可手动关闭 |
| `closed` | 拒绝填写与提交，保留统计，不支持重新开放 |

发布后锁定标题、说明、题目、规则及匿名和重复开关，关闭后也不解锁。截止状态由 `status` 和 `deadline` 共同判断，不另存需要定时维护的 `expired` 状态。仅草稿可永久删除，删除时不修改答卷集合。

草稿保存、发布、截止调整、关闭和删除均采用带条件的单文档原子操作：匹配服务端读取到的原文档，若处理期间内容或状态改变，则拒绝并返回 `409`，避免覆盖新数据。截止调整还在数据库更新时通过 `$$NOW` 检查原截止，防止处理期间跨过截止后恢复接收。这不等于对浏览器长期保留的旧页面提供版本合并。

## 4. 条件跳转与路径计算

跳转规则保存在题目内，由条件 `condition` 与目标 `target` 组成，具体选项、比较值和目标由创建者配置。

| 来源题型 | 条件运算符 | 含义 |
| --- | --- | --- |
| 单选 | `equals` | 选择指定选项 |
| 多选 | `contains`、`contains_all` | 包含某项或全部指定项；后者允许额外选项 |
| 数字 | `gt`、`gte`、`lt`、`lte`、`eq` | 与一个数值比较 |

文本题不配置跳转。目标只能是后方题目，或 `{"kind":"end"}` 表示结束作答并进入提交确认。按数组顺序执行第一条命中规则，无命中则进入下一题；空答不命中条件，数字 `0` 是有效答案。禁止向前跳和循环，保证路径有限。

保存配置时，后端检查题型、条件选项、目标及方向；删除或重排题目和选项时重新检查全部引用，拒绝悬空或非法引用。`surveys/questions.py` 负责配置校验，`surveys/jumps.py` 负责规则判断。

填写时，`responses/logic.py` 从第一题根据当前答案重算有效路径，只校验路径上经过的题目，被跳过的必答题也无需回答。返回修改后，前端清除新路径之外的旧答案；后端仍独立复核，拒绝未知题目、重复答案项和路径外答案，不能仅靠页面隐藏保证正确性。

## 5. 配置校验与答案校验

校验分为两个阶段：创建者保存题目时检查配置是否成立，填写者提交时按已保存配置检查答案。

| 题型 | `validation` 参数 | 主要答案规则 |
| --- | --- | --- |
| 单选 | 无额外参数 | 答案必须为本题有效选项 ID |
| 多选 | `min_choices`、`max_choices` | 选项有效且不重复，数量符合限制；上下限相同表示恰好选择指定数量 |
| 文本 | `min_length`、`max_length` | 去首尾空白后按字符计数，纯空白视为空答 |
| 数字 | `min_value`、`max_value`、`integer_only`、`phone_format` | 数值有限、上下界包含边界；要求整数时不得为小数 |

所有题型通过 `required` 表示必答：非必答允许空答，但非空时仍须符合限制。配置校验检查参数与题型匹配、上下界顺序、选择数量不超过选项数等，避免保存无法满足的约束。

手机号是数字题的可选格式限制，启用时同时要求整数。先检查原始输入为 11 位 ASCII 数字、首位为 1、第二位为 3～9，不接受国家码、空格、连字符或小数，再转换为整数保存；不验证号码是否真实存在，也不根据题目标题自动启用规则。

## 6. 答卷提交、匿名与重复限制

提交依次检查登录身份、问卷开放状态、重复限制、有效路径和答案；校验后再次读取开放状态与截止，以最终检查时刻判定接收，再写入独立答卷。预校验接口复用路径与答案检查，但不保存数据。

禁止重复时，仅“查询是否提交过，再插入”无法防止并发请求同时通过。因此后端根据问卷配置生成 `single_submission=true`，由部分唯一索引保证同问卷、同账号至多保存一份，并捕获重复键错误返回 `409`。允许重复时每次独立保存，历史答卷不被覆盖。

匿名指对问卷创建者隐藏账号身份，填写者仍需登录，系统内部保留 `user_id` 以执行重复限制及统计去重。允许匿名时填写者可自行选择，默认匿名；不允许匿名时拒绝匿名提交。后端以白名单响应排除匿名样本的内部账号标识、答卷 ID 和身份关联，实名样本只展示用户名。填写者在自由文本中自行写入的身份信息不属于自动匿名处理范围。

## 7. 统计口径与实现

统计仅供创建者查看，支持整卷和单题。MongoDB 聚合先按 `survey_id` 筛选，以 `user_id` 升序、`submitted_at` 降序、`_id` 降序排序，再按账号分组：`$first` 取最新整份答卷，`$sum` 计算该账号的提交份数。后端结合问卷配置计算题目结果。

| 指标 | 计算口径 |
| --- | --- |
| 总提交份数 | 该问卷全部成功答卷的数量 |
| 参与人数 | 按内部账号去重的人数 |
| 单选统计 | 最新答卷中各选项人数及有效回答人数 |
| 多选统计 | 最新答卷中各选项被选择的次数 |
| 文本统计 | 最新答卷中的有效文本内容 |
| 数字统计 | 最新答卷中的有效数字及平均值，无样本时返回 `null` |

同账号提交三次分别选 A、B、C，显示 3 份提交、1 人参与，选项统计只计 C。取最新整份答卷后，若该答卷跳过某题，不从历史答卷补回旧答案。空答及跳过不计该题回答人数和数字平均值，数字 `0` 正常计入。

提交时间相同时用 `_id` 降序稳定裁决，这定义了系统的“最新”，不代表精确的并发完成顺序。匿名与实名使用相同内部账号去重，但对外采用最新答卷的匿名状态。统计不另存集合，避免答卷与统计副本不一致。
